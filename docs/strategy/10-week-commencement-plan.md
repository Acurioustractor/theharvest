## Process infrastructure (one-time setup, runs indefinitely)

These three items prevent the January-to-April drift we just corrected from happening again.

### P1 · STRATEGY.md at repo root

**What:** ~20-line file at `/STRATEGY.md` pointing anyone (Nic, future AI session, future Ben) at: strategic plan v2.1, TODOS.md, ops wiki location, archive folder, how to find canonical lease facts.

**When:** Week 1. ~10 min to write + commit.

**Why:** Right now a visitor to the repo sees a code project and doesn't know the strategy layer exists. One file fixes discoverability at the GitHub level.

**Owner:** Ben.

### P2 · Monthly 15-min strategic-plan review

**What:** First Monday of each month (next: **Mon 4 May 2026**, 15 min). Open `docs/strategy/the-harvest-strategic-plan-notion.md`. Scan Pre-Commencement Checklist + Risk Register + Success Metrics. Confirm what's on-track, note what's slipping, update statuses inline.

**When:** Recurring first Monday of each month. First run Week 2 (4 May).

**Why:** This is the drift-detection mechanism. 15 min once a month is cheaper than the ~90 min we spent today catching the January-to-April drift.

**Owner:** Ben solo first 3 months; expand to Ben + Nic once operational rhythm settles.

### P3 · `/schedule` recurring TODOS-hygiene agent

**What:** A background AI agent that runs on cron — say every 1st of the month at 9am — that opens `TODOS.md`, checks if any deferred items have hit their deadline, flags items where the deadline is within 30 days, and pings Ben.

**When:** Set up Week 1-2 using the `/schedule` skill. One-time setup.

**Why:** TODOS.md deferred items are typed-in promises with real dates (Governance Mar 2027, Exit Vision Month 6, Foundation/DGR Month 9). Without a recurring ping, they silently age past their deadlines.

**Owner:** Ben to set up. Agent is autonomous after.

**Dependencies:** None. Can happen Week 1 in parallel with everything else.
