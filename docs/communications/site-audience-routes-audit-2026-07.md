# Site audience + routes audit: every page, six kinds of visitor

Created 2026-07-07. Method: one review agent per public page (19 pages) plus one
cross-site routing agent, each grading the live code (and the two pages with live
`editable_content` overrides: works, membership) against the six audience types below.
Constraints applied: the comms map (`now-open-communications-map-2026-07.md`), the
voice guide (`brand-and-voice-guide.md`), no fabricated facts. Raw per-page findings
are in the appendix at the bottom; this front section is the synthesis and build order.

Grounding data (queried 2026-07-07): `pulse_responses` has 1 row (a test),
`community_submissions` has 6 rows (all tests). The capture doors work; no real
community input has arrived through the site yet. That is the problem this audit
exists to fix: the doors are built, the routes to them are weak.

## The six audience types

Each type arrives with questions. The site wins when every page they land on either
answers the question or hands them to the page that does.

1. **The curious local.** Hinterland resident. Asks: what is this place now, can I
   just turn up, when, is it free, what happened to the old Green Harvest nursery?
2. **The visitor family.** Weekend day-tripper, often with kids. Asks: what can we
   actually DO, how does the pizza thing work, what times, is it kid-friendly,
   do we book, where is it?
3. **The maker, grower or artist.** Asks: how do I get on the shop shelf, use the
   art space, run a workshop, what is the deal, who do I talk to?
4. **The future member.** Visited once or follows socials. Asks: how do I stay in
   the loop, what does free membership actually get me, what is coming?
5. **The helper with hands.** Asks: when is the next work day, what would I do,
   do I need experience or tools?
6. **The idea-bringer.** Has a suggestion, feedback, or wants to host something.
   Asks: how do I tell them, will a human respond, can I use the space?

## What the audit found (the short version)

- **The pizza rhythm is the site's best answer and it lives on two pages.** Nearly
  every page fails "can I just turn up, and when?" while home and /whats-on hold the
  answer. Twelve separate page audits independently proposed the same fix: put the
  weekend rhythm + "no booking needed" + "dates land with members first" on the page.
  That is a shared component, not twelve bespoke edits.
- **The maker/grower/artist route is the most broken.** "Works" in the nav reads as
  artworks; the real doors (shop shelf EOI, art space, workshops via venue-hire) are
  scattered and footer-only. Every home work-card raises an ask ("sawmill leads,
  timber hands") with no reply path next to it.
- **Membership is the answer to four audiences and it is missing from the nav.**
  The persistent header has no Membership item (only the CTA button on desktop);
  interior-page arrivals from search or socials lose the door. And the "This week's
  dates" button jumps to Mighty with no "free to join" cue, so it can read as a paywall.
- **The ideas/feedback loop exists but does not say a human answers.** /pulse fails
  silently on submit errors, still asks pre-opening questions ("Have you heard of
  The Harvest?"), has em-dashes in live copy, and nothing anywhere says "a person
  reads every one and replies."
- **Honesty debt.** /whats-on hero promises "Markets, workshops" with none listed;
  /venue-hire shows named spaces + amenity grids the comms map explicitly forbids;
  /story timeline marks "Site Development" complete; a "1,300 residents" figure is
  stated as fact on four pages with no source.
- **Privacy items (P0, Ben's call, listed below).**

## The build order (page by page, as agreed)

### Phase 0: shared infrastructure (unlocks everything else)
- **`VisitStrip` shared component**: pizza rhythm, "turn up, no booking needed",
  "weeks can vary, dates land with members first", one members-page link with
  "free to join" microcopy. Drop into: /works, /works/:slug, /shop, /contact,
  /witta, /gather, /june-20, /stories, /membership, /get-involved, /venue-hire,
  /blog empty state.
- **Nav**: add Membership to `pageNavLinks`. **Footer**: add Story (/story),
  Stories (/stories), Photo Wall (/photo-wall).
- **Shared chrome on /pulse and /photo-wall**: replace BauhausFooter with
  SiteNav/SiteFooter so socially-shared pages route back into the site.
- Decide /gather: keep as gatherings story page (linked from /whats-on) or retire.

### Phase 1: the four highest-traffic pages
- **/ (home)**: upgrade ThisWeekStrip (no booking + Dennis + relabel button
  "Dates on the members page" + free-to-join microcopy); add one maker/helper door
  line under the works intro; fix Kids' Area card image mismatch.
- **/whats-on**: honesty pass on hero + categories (drop "Markets, workshops" until
  real, hide filter row when zero events); add address + times on RSVP day labels;
  link the members page in the work-days card.
- **/story**: pizza times + members link in Gatherings card; point "Plan Your Visit"
  at /whats-on; move no-booking line up; fix "Site Development" complete -> in
  progress; single closing CTA.
- **/membership**: fix the headless hero note card (new default + clear the empty
  override); concrete Gather lane (pizza rhythm); "just want to have a look first?"
  exit to /whats-on.

### Phase 2: the participation doors
- **/get-involved**: work-days line with members-page path; just-visiting strip;
  "Selling on the shop shelves" option in the local business form; fix "journey"
  placeholder (banned word).
- **/shop**: come-and-see-it line; buyer/follower door ("opening dates land with
  members first"); routing line to /get-involved for workshops/art space.
- **/works + /works/:slug**: Sophie code fix; visit strip; real doors on the works
  that ask for hands; closing CTA points somewhere real.
- **/contact**: pizza rhythm in VISITS block; "good things to write to us about"
  framing line; member-door on the thank-you screen; resolve phone/email P0s.
- **/venue-hire**: strip to the honest enquiry door the comms map requires (kill
  named spaces/amenities grid); come-and-see-it block.

### Phase 3: the listening loop
- **/pulse**: error toast on failed submit (currently silent!); post-opening
  question refresh; em-dash sweep; "a human reads every response" + visit line on
  thank-you screen.
- **/photo-wall**: split idea capture from portrait finder; honest empty state
  with visit line; etiquette/takedown note; moderation queue (backend, with P0 3).
- **/blog, /witta, /people, /stories, /june-20**: per-page punch lists in the
  appendix (dead Load-more button, name The Green Harvest on /witta, consent
  checks, empty states, member doors).

### What each phase needs
Phase 0-3 code changes are all night-shift safe (local code, committed on the
branch, deployed only via the manual promote). The P0 list above is day-shift:
privacy calls, consent checks, one inbox verification, one census lookup.
